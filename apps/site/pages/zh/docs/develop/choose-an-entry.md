# 选择 Code、Agent 或 Workflow

先写下一条输入和用户会认可的验收证据，再为每个命令选择入口。

| 业务条件 | 入口选择 |
| --- | --- |
| 做法固定，结果可以复算 | 用 **Code** 计算金额、应用照片参数或写入字节。需要让 Agent 调用其中一项操作时，将它封装成 Tool。 |
| 下一步取决于素材 | 用 **Agent**，声明目标、可用工具和完成条件。例如 Agent 决定简报采用哪些版式，工具实际写出可编辑的演示文稿。 |
| 阶段必须按序发生 | 用 **Workflow**，例如先审核规格，再实现，最后验证补丁。阶段内部可以调用 Agent。 |
| 已有可独立分发的包负责其中一项工作 | 在父包声明**子 Loom**，通过 Workflow 调用它的指定命令。 |

**Harness** 由宿主配置，可选 Mastra 或 OpenCode，负责执行 Agent。作者声明模型槽位、能力和工具。Agent 可以自行澄清缺失信息；需要保证业务先后顺序时，再用 Workflow 表达。[Agent 和工具](./components) · [工作流与子 Loom](./workflows)
