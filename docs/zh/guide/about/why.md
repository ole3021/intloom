# 为什么需要 IntLoom？

开发任务往往需要澄清需求、确认设计、修改文件、执行检查，再判断证据是否充分。把这些活动写成明确的 Workflow，可以为每个步骤规定职责、输入和下一步的流转方式。

## IntLoom 提供什么

- **明确流程：** 阶段、步骤和 outcome 决定工作如何前进或返回修改。
- **人的决策：** Code 提问或请求确认，回答后继续同一个 Run。
- **声明能力：** 每个 Agent 使用该 Step 分配的 Tools、Skills 和输出 Schema。
- **结果留存：** Artifact 表示当前正式产物，Record 保存追加的业务证据。
- **多种入口：** CMD、TUI、MCP 连接同一个项目 Service。

Intent Workflow 把这些机制用于软件开发：先确认需求与设计，再实施，最后保存验证发现和证据。

## 何时使用

当任务需要可重复的流程、明确决策、本地项目操作，或需要事后检查结果时，可以使用 IntLoom。一个简短、独立的问题可能无需 Workflow。

Run 完成表示流程到达了声明的终点。交付是否满足目标，需要结合保存的报告和检查结果判断。参见 [Intent 结果说明](../intent/results.md)。
