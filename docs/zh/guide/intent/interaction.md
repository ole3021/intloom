# Intent 中的用户决定

提问与确认都是真实的 Code 交互。Agent 可以提出问题和草稿，不能代填用户回答或批准。

## 需求和设计确认

Specification 展示基线、完整需求提案、累计变化、本轮范围、Coverage 和实际回答。Solution 展示固定需求、设计变化、实施依赖、验证职责和风险。

只确认展示的版本。反馈返回尚未提交的草稿；提案或依据变化会使旧确认失效。正式提交后若需实质修改，开启新 Run。

## 部分交付

实施未完成时，Code 展示精确候选、计划项、实际变化、失败或缺失的检查及剩余工作。明确选择部分交付，才允许该候选进入 Validation；不会缩减验收目标，也不代表验收通过。来源不明的外部修改需要另行决定是否纳入这些具体变化。

## 取证选择

Validation 展示固定依据与候选、已有证据、未知事项及受影响的取证任务。可选择继续、暂停或仅结束列出的取证。沉默不是许可。结束后保留失败和未知，仍需整理完整报告并经 Code 检查后发布。

没有结算回执的原执行必须先核查，不能直接继续。取消 Run 不回滚正式 Record 或项目文件。中断后检查同一个 Run，避免重复启动工作。

客户端操作见 [Run 管理](../usage/runs.md)，结论含义见[结果说明](./results.md)。
